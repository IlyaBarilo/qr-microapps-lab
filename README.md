# QR Microapps Lab

Локальный инструмент для проверки и упаковки небольших автономных HTML-приложений в QR-код. Готовая лаборатория работает одним HTML-файлом: без сервера, установки, CDN и подключения к Интернету.

Лабораторию можно использовать на занятиях по разработке с ИИ: задавать требования к приложению, проверять результат генерации и исправлять найденные нарушения.

## Попробовать за 2 минуты

1. [Откройте онлайн-демо](https://ilyabarilo.github.io/qr-microapps-lab/).
2. Выберите готовый пример — он загрузится автоматически.
3. Измените код или оставьте без изменений.
4. Нажмите «Проверить и создать QR».
5. Посмотрите автоотчёт и результат обратного декодирования.
6. Проверьте работу приложения во встроенном предпросмотре. Затем можно скачать HTML или QR.

## Автономный запуск

1. Скачайте [qr-microapps-lab.html](https://github.com/IlyaBarilo/qr-microapps-lab/releases/latest/download/qr-microapps-lab.html).
2. Откройте файл в современном браузере.
3. Загрузите собственный HTML или выберите автоматически загружаемый готовый пример, затем нажмите «Проверить и создать QR».

Стили, исходный код, QRCode.js, jsQR, анализаторы Acorn и CSS Tree и обязательные лицензионные уведомления уже встроены в этот файл. Для обычного запуска остальные файлы репозитория не нужны.

> QR с `data:` URL может распознаться камерой как текст, а не как обычная веб-ссылка. Возможность открыть его зависит от сканера, браузера и операционной системы телефона.

## Что умеет лаборатория

### Подготовка и проверка HTML

- принимает готовый HTML или собирает тест в визуальном конструкторе;
- сокращает CSS и JavaScript и показывает экономию;
- проверяет структуру HTML, внешние зависимости, мобильный интерфейс и сенсорное управление;
- запускает приложение в изолированном предпросмотре с запретом сети и сообщает об ошибках выполнения;
- позволяет изменять сложность совместимых приложений.

Для создания игр с ИИ есть [спецификация и готовый промпт](spec_game_creation_ru.md). Они также доступны в лаборатории без Интернета. Подробности оптимизации, проверок и отчётов — в [руководстве пользователя](docs/user-guide-ru.md#подготовка-и-проверка-html).

### Создание и проверка QR

Создаёт QR с автоматическим выбором коррекции, проверяет точность восстановления содержимого и показывает код во весь экран. Можно загрузить готовое QR-изображение для анализа и подготовить тестовые листы для экрана или бумаги. [Параметры и диагностика QR](docs/user-guide-ru.md#создание-и-проверка-qr).

### Экспорт и печать

Сохраняет HTML, QR в PNG или SVG, профиль, отчёт и файл проекта. Печатает QR на листе A4 с названием и инструкцией. [Форматы и настройки печати](docs/user-guide-ru.md#экспорт-и-печать).

### Черновики и перенос работы

Поддерживает автосохранение, восстановление и возврат к предыдущей версии работы. Скачанный файл черновика позволяет перенести незавершённую работу в другой браузер или на другой компьютер. [Сохранение и перенос черновиков](docs/user-guide-ru.md#черновики-и-перенос-работы).

### Встроенные примеры и их описание

Встроены одиннадцать примеров: тест, «Как думает компьютер?», «Турнирная сетка», «Пакет в сети», «Разбей блоки», «Брандмауэр», «Успей в релиз», «Киберрефлекс», «Кибертрасса 2.5D», «Киберлабиринт 2.5D» и «Карьерный компас».

«Кибертрасса 2.5D» и «Киберлабиринт 2.5D» создают видимость объёма двумерными методами. Для примеров с документацией доступна кнопка «Описание примера». [Механика и описание примеров](docs/user-guide-ru.md#встроенные-примеры-и-их-описание).

## Как контролируется результат ИИ

Лаборатория не считает сгенерированный HTML готовым только потому, что он открылся в браузере. Работа строится как последовательность контрольных точек:

```text
замысел преподавателя → спецификация → HTML от ИИ → автоматические проверки
→ независимое декодирование QR → испытание на телефоне → применение
```

Автоматически проверяются измеримые технические свойства: автономность, вместимость, структура HTML, мобильный интерфейс, запрещённые операции и точность цифрового восстановления. Содержание, удобство и работа на конкретном телефоне требуют отдельной оценки человеком.

## Проверка на реальных устройствах

Приложение из QR удалось запустить на Redmi Note 13 Pro, Redmi Note 8 Pro, Redmi Note 6 Pro и Huawei Mate X6. На трёх Redmi дополнительно проверена работа без Интернета. На Huawei Интернет не отключали.

Результат зависит от сканера: некоторые штатные камеры не обнаружили QR, а успешный запуск включал копирование распознанного текста в браузер. Конфигурации, результаты и скриншоты собраны в [протоколе устройств](docs/device-testing-ru.md), описание тестовых листов — в [руководстве пользователя](docs/user-guide-ru.md#проверка-на-реальных-устройствах).

Ранняя версия проекта использовалась на учебном занятии, но результаты проверки телефонов тогда не протоколировались. Опубликованные результаты получены в отдельных испытаниях.

## Разработка

Для сборки требуется Node.js 22 или новее. Редактировать нужно файлы в `editor/`; корневой автономный HTML является результатом сборки.

```text
npm --prefix tests run build:standalone
npm --prefix tests run check
```

Полная браузерная проверка после установки зависимостей:

```text
npm --prefix tests ci
npm --prefix tests exec -- playwright install chromium firefox webkit
npm --prefix tests run check:all
```

- `npm --prefix tests run build:standalone` обновляет корневой автономный HTML.
- `npm --prefix tests run build:html-parser` воспроизводит локальную браузерную сборку parse5 из зависимостей, зафиксированных в `tests/package-lock.json`. Для обычной сборки лаборатории эта команда не нужна.
- `npm --prefix tests run check` запускает модульные тесты, проверяет актуальность сборки и структуру репозитория.
- `npm --prefix tests run test:standalone-browser` открывает HTML напрямую через `file://` в Chromium, проверяет отсутствие сетевых запросов и печать листов в PDF.
- `npm --prefix tests run test:e2e` проверяет основные пользовательские сценарии в Chromium, Firefox и WebKit: черновики, импорт и экспорт, автономный запуск, предпросмотр и адаптивный интерфейс. Для одного браузера добавьте `-- --project=firefox` (или `chromium`, `webkit`).

CI и публикация релиза запускают проверки во всех трёх браузерах. Используются тестовые сборки Playwright; WebKit в этих проверках не подтверждает работу камеры или Safari на настоящем iPhone. Тестовые браузеры нужны только для разработки и не включаются в автономный HTML.

## GitHub Pages

Единый workflow `Publish release` автоматически запускается при публикации GitHub Release и извлекает проект из соответствующего тега. Он один раз проверяет выбранную версию, подставляет тег в интерфейс, прикрепляет автономный HTML к релизу и публикует тот же файл на GitHub Pages. Содержимое демо, отображаемая версия и скачиваемый релиз поэтому соответствуют друг другу. Для повторной публикации существующего релиза workflow можно запустить вручную, указав его тег. Обычный push в `main` обновляет исходники и запускает CI, но не меняет стабильное демо. Исходный каталог `pages/` не нужен для локального запуска лаборатории.

## Релизы

При публикации GitHub Release workflow `Publish release` подставляет тег релиза в интерфейс и автоматически добавляет готовый `qr-microapps-lab.html`. Создаваемые GitHub архивы `Source code` остаются доступны отдельно.

В отображаемых версиях и тегах конечный нулевой номер исправления опускается: `v0.1` вместо `v0.1.0`, `v1.2` вместо `v1.2.0`. Ненулевой номер сохраняется полностью, например `v0.1.2`.

Порядок подготовки релиза и разбор ошибок CI описаны в [руководстве разработчика](docs/development-ru.md#подготовка-следующего-выпуска).

## Ограничения и безопасность

Корректно созданный QR не гарантирует запуск штатной камерой любого телефона. Результат зависит от физического размера модулей, экрана, освещения, сканера, ОС и того, разрешает ли браузер открывать `data:` URL.

Обратное декодирование jsQR доказывает цифровую корректность сформированных пикселей, но не заменяет проверку камерой реального устройства.

Предпросмотр использует sandbox, CSP внутри запускаемого документа и ограничение навигации iframe на странице лаборатории. Это уменьшает риск, но не защищает полностью от пользовательского кода, способного зависанием перегрузить вкладку. Не запускайте неизвестный HTML без необходимости.
