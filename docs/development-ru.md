## Подготовка следующего выпуска

1. Выполните сборку и `npm --prefix tests run check:all`. Исправьте обнаруженные ошибки до подготовки релиза.
2. Подготовьте описание изменений относительно предыдущего релиза и назначьте номер версии по [правилам нумерации](../README.md#релизы).
3. Сверьте README и руководство пользователя с возможностями публикуемой версии. Обновляйте результаты испытаний только по фактически проведённым проверкам.
4. Зафиксируйте и отправьте изменения. Дождитесь успешного CI именно для коммита, который войдёт в релиз.
5. Создайте тег для проверенного коммита и опубликуйте GitHub Release этого тега. Workflow проверит выбранную версию, добавит автономный HTML к релизу и обновит Pages.
6. Откройте демо и скачанный HTML, проверьте номер версии и пройдите «Быстрый старт». Проверьте ссылки на методику и автора, а также отображение при ширине 1260 px.

## Разбор ошибок браузерных проверок

При падении браузерных сценариев CI и публикация сохраняют отчёт Playwright, снимки ошибок и трассировки повторной попытки в артефакте на 14 дней. Для CI артефакт называется `browser-failure-report`, для публикации — `release-browser-failure-report`.

Откройте отчёт в каталоге `playwright-report`: он содержит название упавшего сценария и сообщение об ошибке. Дополнительные материалы находятся в `test-results`. После исправления повторите упавший сценарий, затем выполните полный набор проверок перед выпуском.
